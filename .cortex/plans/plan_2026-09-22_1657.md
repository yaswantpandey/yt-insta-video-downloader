## Build: Video Downloader Website (Instagram Reels / YouTube videos / YT Shorts)

**Stack:** Python Flask backend + `yt-dlp` library, single-page vanilla HTML/CSS/JS frontend. No build step, runs locally with `python app.py`.

### Files
- `requirements.txt` — flask, yt-dlp
- `app.py` — Flask server:
  - `POST /api/info` → validates URL (allowlist: youtube.com, youtu.be, instagram.com), extracts metadata with yt-dlp (`skip_download`), returns title, thumbnail, duration, uploader, platform, and a list of downloadable format options
  - `GET /api/download?url=&format_id=` → streams the file to the browser via a temp dir + `send_file`, then cleans up
  - URL validation to prevent SSRF/arbitrary-host fetches; no shell interpolation (library API only)
- `templates/index.html` — paste-URL form, platform-aware result card (thumbnail, title, duration), quality picker, download button, error/loading states
- `static/style.css` — dark responsive UI
- `static/app.js` — fetch calls, render results, trigger download
- `README.md` — setup + ffmpeg note

### Key technical decisions
- **Quality options:** offer progressive (video+audio in one file) MP4s directly, plus an "audio only (m4a)" option. Merged high-res (1080p+ video-only + audio) requires **ffmpeg, which is not installed** — I'll detect ffmpeg at startup and only expose merge-requiring formats when present, with a UI note otherwise.
- **Instagram:** public Reels work without auth; private/login-walled posts will return a clear error. Optional `cookies.txt` support via env var for logged-in content.
- Deps installed into a local `.venv` so the global Python stays clean.

### Note on scope
Downloading from these platforms is against their ToS; this is fine for personal/own-content use but I'll put a short disclaimer in the README and footer.
